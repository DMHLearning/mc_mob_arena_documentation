**Paper-Arena** - сервер для того, чтобы объединять игроков с основной мини-игрой.

На аренах игроки испытывают основной игровой цикл. Игроки сражаются с волнами монстров и их задача выжить наибольшее количество волн. Каждую 5-ую волну можно выбрать вариант “Продолжить игру” или “Покинуть арену”.

В случае продолжении игры - волны продолжаются и становятся сложнее, а в случае покидания арены - прогресс и накопленные ресурсы сохраняются у игрока и игрок перемещается в лобби, соответствующая арена сбрасывается до изначального состояния и готова принимать других игроков.

## Самописные плагины
#### `arena-runtime` (Paper)

**Задача:** ядро игровой сессии (одна арена = один рантайм/контекст).
- Управление жизненным цикла арены: `IDLE -> PREPARE -> RUNNING -> FINISH -> RESET`.
- Волны, спавн, трек прогресса, награды, таблицы результатов.
- Вся логика мини-игры и самой арены.
- Сильная изоляция: runtime арены не лезет “в соседние арены”.

Вся игровая механика, сущности, мир, регионы, спавн - это серверная часть и прямое взаимодействие с миром, а не только сетевая часть.

#### `arena-world-manager` (Paper)

**Задача:** управление картами/регионами/схематиками через WorldEdit/WorldGuard.

- Подготовка арены: копирование/восстановление структуры, очистка сущностей/дропа.
- Создание/обновление регионов WG: запреты, флаги, защитные контуры.
- Сброс арены после сессии, чтобы вернуть мир “как было”.

Мир/регионы - это инфраструктурная функция. Её нужно уметь переиспользовать и тестировать независимо от игровой логики.

#### `arena-observability` (Paper)

**Задача:** единая точка метрик/сигналов/инцидентов.
- Публикация метрик через UnifiedMetrics.
- Снапшоты здоровья сервера: `HEALTHY/DEGRADED/CRITICAL` по заранее заданным порогам для обучения.
- Детекция “типовых отказов”: зависшие волны, некорректный сброс арены, слабая отзывчивость мобов, рост MSPT, ошибки в ключевых обработчиках.
- Отправка агрегированных событий наружу (в `arena-matchmaker`).

Реальные показатели живут на Paper. На Velocity мы их лишь агрегируем.
