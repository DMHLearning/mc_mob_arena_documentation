## 1. Назначение документа

Данный документ описывает **пользовательские истории** для системы мини-игры *Minecraft Mob Arena*.

User Stories используются для:
- формализации требований через призму персон;
- привязки игрового поведения к состояниям гомеостаза;
- выявления критических точек отказа;
- последующего проектирования реализации и тестирования.

Истории описывают **ожидаемое поведение системы**, а не конкретные технические решения.

## 2. Структура пользовательской истории

Каждая история включает:
- связанную персону;
- основной сценарий;
- критерии приёмки;
- чувствительность к отказам;
- связь с гомеостазом.

## 3. Истории для персоны P-01 — Новичок

### US-01: Первый вход на арену

**Как** Новичок  
**Я хочу** зайти на арену и начать бой  
**Чтобы** понять, как работает мини-игра

**Критерии приёмки:**
- игрок без ошибок попадает с лобби на арену;
- первая волна стартует без задержек;
- игрок понимает причину своей смерти или победы.

**Критичность отказа:**
- смерть из-за бага → критический отказ системы.

**Связь с гомеостазом:**
- допустимо только состояние HEALTHY.

### US-02: Предсказуемая ранняя сложность

**Как** Новичок  
**Я хочу** чтобы первые волны были предсказуемыми  
**Чтобы** адаптироваться к механикам

**Критерии приёмки:**
- отсутствие резких скачков сложности;
- корректный расчёт волн;
- стабильный игровой процесс.

**Связь с гомеостазом:**
- переход в DEGRADED недопустим на ранних волнах.

## 4. Истории для персоны P-02 — Регулярный игрок

### US-03: Честный рост сложности

**Как** Регулярный игрок  
**Я хочу** ощущать постепенный рост сложности  
**Чтобы** мой прогресс был осмысленным

**Критерии приёмки:**
- сложность растёт консистентно;
- изменения объяснимы;
- система не нарушает ожидания без причины.

**Критичность отказа:**
- неконсистентные правила → высокий негатив.

### US-04: Корректная фиксация прогресса

**Как** Регулярный игрок  
**Я хочу** чтобы мой прогресс сохранялся  
**Чтобы** мои усилия не пропадали

**Критерии приёмки:**
- прогресс сохраняется при добровольном выходе;
- прогресс сохраняется при поражении;
- потеря прогресса невозможна без soft-fail.

**Связь с гомеостазом:**
- DEGRADED допустим;
- FAILED требует корректного завершения.

## 5. Истории для персоны P-03 — Хардкорный игрок

### US-05: Предельная нагрузка

**Как** Хардкорный игрок  
**Я хочу** дойти до экстремальных волн  
**Чтобы** проверить пределы системы

**Критерии приёмки:**
- система не падает при высокой нагрузке;
- деградация происходит управляемо;
- смерть игрока объяснима.

**Связь с гомеостазом:**
- допустимы DEGRADED и CRITICAL;
- FAILED допустим только с сохранением прогресса.

### US-06: Честное поражение

**Как** Хардкорный игрок  
**Я хочу** умирать только по игровым причинам  
**Чтобы** принимать поражение как результат своих действий

**Критерии приёмки:**
- отсутствие багов, влияющих на бой;
- отсутствие лагов, влияющих на исход.

**Критичность отказа:**
- баг-индуцированная смерть → системный отказ.

## 6. Истории для персоны P-04 — Оператор

### US-07: Наблюдаемость состояния системы

**Как** Оператор  
**Я хочу** видеть текущее состояние системы  
**Чтобы** вовремя реагировать на деградацию

**Критерии приёмки:**
- отображается текущее состояние гомеостаза;
- понятны причины переходов;
- видны автоматические действия.

### US-08: Минимизация пользовательского ущерба

**Как** Оператор  
**Я хочу** чтобы система минимизировала ущерб игрокам  
**Чтобы** сохранить доверие

**Критерии приёмки:**
- soft-fail применяется корректно;
- прогресс сохраняется;
- игроки информированы.

## 7. Итоговые положения

- User Stories связывают архитектуру с пользовательским восприятием.
- Каждая история обязана быть совместима с гомеостазом.
- Истории служат основой для будущей реализации и тестирования.
