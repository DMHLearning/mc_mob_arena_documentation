## 1. Назначение документа

Данный документ описывает **пользовательские и системные потоки** (User Flow) мини-игры *Minecraft Mob Arena*.

Цель документа:
- формализовать поведение игрока и системы во времени;
- зафиксировать жизненный цикл игровой сессии;
- определить точки перехода между состояниями гомеостаза;
- обозначить места деградации, soft-fail и самовосстановления.

User Flow рассматривается не только как UX-последовательность, но как **совместный процесс игрока и системы**.
## 2. Участники потоков

- Игрок (одиночный или в составе команды)
- Лобби
- Арена
- Система управления аренами
- Система мониторинга (пассивный участник)
## 3. Глобальный пользовательский поток

```
Подключение к серверу
        ↓
Попадание в лобби
        ↓
Выбор арены
        ↓
Формирование команды
        ↓
Запуск игровой сессии
        ↓
Цикл волн (повторяется)
        ↓
┌───────────────┬─────────────────┐
│ Добровольный  │ Полное поражение│
│ выход игрока  │ всей команды    │
└───────────────┴─────────────────┘
        ↓
Завершение сессии и фиксация прогресса
```

## 4. Поток: Лобби → Арена

### 4.1 Описание
Игрок подключается к серверу и попадает в лобби. Из лобби он может:
- выбрать доступную арену;
- дождаться других игроков;
- выйти из системы без последствий.

### 4.2 Ожидания системы
- Лобби не должно зависеть от состояния арен;
- Перегрузка арен не должна блокировать лобби;
- Информация о доступности арен должна быть актуальной.

### 4.3 Потенциальные деградации
- Ограничение количества доступных арен;
- Увеличение времени ожидания.

## 5. Поток: Запуск игровой сессии

### 5.1 Описание
После формирования команды система:
- инициализирует арену;
- рассчитывает стартовые параметры сложности;
- переводит арену в активное состояние.

### 5.2 Критические точки
- Ошибка инициализации арены;
- Недостаток ресурсов.

### 5.3 Поведение при сбоях
- Отмена запуска с возвратом игроков в лобби;
- Сообщение игрокам о причине.

## 6. Поток: Цикл волн

### 6.1 Базовый цикл

```
Начало волны
    ↓
Расчёт сложности
    ↓
Спавн мобов
    ↓
Бой
    ↓
Проверка состояния команды
    ↓
Завершение волны
```

### 6.2 Динамика сложности
- Сложность рассчитывается по формуле ранга игроков;
- Система имеет право корректировать результат формулы;
- Фактическая сложность может отличаться от расчётной.

### 6.3 Вмешательство гомеостаза
- При росте нагрузки возможен переход в DEGRADED;
- Упрощение ИИ мобов и снижение количества мобов;
- Изменение таймингов между волнами.

## 7. Поток: Добровольный выход

### 7.1 Условия
После каждой 5-й волны игрок или команда могут:
- забрать накопленный лут;
- завершить сессию добровольно.

### 7.2 Поведение системы
- Фиксация прогресса;
- Корректное завершение арены;
- Освобождение ресурсов.

## 8. Поток: Поражение команды

### 8.1 Условия
- Все игроки команды погибли.

### 8.2 Поведение системы
- Немедленное завершение сессии;
- Частичная фиксация прогресса;
- Информирование игроков о причине поражения.

## 9. Soft-Fail в пользовательских потоках

### 9.1 Триггеры
- Критическое падение производительности;
- Нестабильное состояние арены;
- Повторяющиеся ошибки.
### 9.2 Поведение
- Принудительное завершение сессии;
- Максимально возможное сохранение прогресса;
- Возврат игроков в лобби.
## 10. Связь с мониторингом
Каждый пользовательский поток имеет:
- измеримые точки входа и выхода;
- показатели длительности;
- условия отклонения.

User Flow служит основой для:
- синтетических тестов;
- игровых метрик;
- триггеров самовосстановления.
## 11. Итоговые положения
- User Flow описывает поведение системы во времени.
- Любая деградация должна быть объяснима в рамках потоков.
- Потоки обязаны оставаться корректными при изменении реализации.
